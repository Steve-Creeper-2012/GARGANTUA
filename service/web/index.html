GARGANTUA 是什么

            一个单机跑得动的通用 token 模型：默认配置约 10 亿参数
            （4+6 blocks、每 block 5 个 FFN；可用 d_model / block 数 / 共享权重调规模），权重按需加载，
            训练/推理/编解码全在本机完成，不依赖任何云服务。它不做「聊天框套壳」，
            而是把文本、音频、图像、视频、图元（矢量绘图）统一压进同一条
            token 流里，用同一个 Transformer 学。
          

            核心主张只有一句：一切模态最终都是 token + 时间步。
            时间步 { … } 是原子单位——压缩、丢弃、滑窗都不许把它切开。
          
1. 数据流：从任意模态到同一条 token 流
2. 一个 block 里到底有什么

            每个 block 的顺序是冻结的（2026-11-04 重排）：KDA → FFN → KDA → FFN →
            KDA → FFN → MLA-CSA → FFN → MLA-HCA → FFN → AttnRes。
            每个递推/注意力子层之后立刻接一个 FFN 做逐位置变换，5 个 FFN 是独立实例
            （GLU，d_ff=4096）；两个 MLA 视图分别是 CSA（4:1 可学习压缩 + 检索）与
            HCA（32:1 全局概括）。10 个计算子层各自先做一次 AttnRes 深度聚合与 RMSNorm，
            再累加进残差流；块末还有零初始化标量门把块输入混回输出。
          

            建模时可选权重模式：默认「分离权重」，encoder / decoder 各持一套
            block 参数（默认 4 / 6 层）；选「共享权重」则
            enc_blocks[i] 与 dec_blocks[i] 逐层共用同一批参数，因此两侧层数
            必须相等。共享只绑定参数、不合并实例——encoder 依旧双向，
            decoder 依旧按时间步因果；权重文件只落一份，参数量与磁盘占用约减半。
            模型宽度 d_model 建模时也可选（默认 1024，128 的倍数、无上限）：
            它只改语义向量宽度，注意力头数/头维、MLA 低秩秩与 FFN 隐藏宽度仍是冻结架构值。
          
3. 上下文：完整段 + 压缩段

            上下文 = 完整 1024 token + 压缩 3072 token。完整段不压缩，原样保留；
            压缩段是同一段内容的两份压法——CSA 检索视图（4:1）与 HCA 全局概括视图（32:1）。
            两个视图都读【压缩段 + 全部完整段】。压缩以时间步为原子，绝不跨步拆分。
          
4. 词表：冻结的契约头 + 可变的可见区

            词表不是「一个 txt」，而是一个文件夹（vocabs/<name>/{vocab.vfc, config.json}）。
            ID 必须严格连续 0..N-1，一个空位都不留——空位也要吃一行 embedding。
            前 9614 个 ID 是架构契约头（special 6 + system 3 + draw 9605），
            所有词表逐字一致、不可增删；可见区（数字 / 空白 / 符号 / emoji / 中日韩 / 英文 / 兜底字母）长度由各词表自己决定。
          
5. 图元输出：先声明画布，再画

            一张图 = 1 段画布声明（<x> 数字… <x/> <y> 数字… <y/>，
            1..1920×1080 任意尺寸）+ N×9 个图元 token。
            每个图元 9 个字段，各自独立 bin 区间：x、y、w、h
            全部 1 token = 1 像素（上限即画布上限 1920×1080）、
            theta（3 bin/度，≥90° 交换宽高）、
            shape（背景/矩形/椭圆）、r/g/b（10 bit，1024 档）。
          
6. 进程结构：常驻 server + 按需子进程
server/ 是一个常驻的轻量 HTTP 服务（纯标准库，不 import torch）；
            训练、推理、编解码这些重活全部交给 service/* 的子进程，
            用 JSON-lines over stdin/stdout 通信，空闲超时自动退出。
            好处是：换模型/崩一个服务不会带走整个应用，内存也能真正还回去。
