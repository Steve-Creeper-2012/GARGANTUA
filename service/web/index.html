总上下文 = 完整 + 压缩（默认 1024+3072=4096 token）。KV 分两段：完整段不压缩； 压缩段是同一段内容的两份压法——CSA 检索视图（默认 4:1）与 HCA 全局概括视图（默认 32:1）， 两者都读【压缩段 + 全部完整段】。压缩分组以时间步为原子，绝不跨步拆分。
权重模式：默认「分离权重」，encoder / decoder 各有一套参数。 选「共享权重」时 enc_blocks[i] 与 dec_blocks[i] 逐层共用同一批参数， 两侧 block 数强制相等（dec 输入框会锁定并自动跟随 enc）； 参数量与权重文件约减半，但 encoder 仍双向、decoder 仍因果。 d_model 只改语义向量宽度（128 的倍数，无上限，默认 1024）； 注意力头数/头维、MLA 低秩秩、FFN 隐藏宽度仍是冻结架构值。 宽度越大，embedding 与 lm_head 占用内存越多。
MoMW（默认关闭）：启用后在第一个 Block 之后多一条无训练三阶段记忆阀门。 阶段一用类别锚点（模型自己的词表编码代表文本后取 Embedding 均值，不依赖硬编码 token ID） 与输入算余弦做冷启动路由；阶段二用 Oja 规则每步在线跟踪 SᵀS 的主方向 E （O(d) 更新、冷启动一次幂迭代），按 γ=1−e^(−writes/k) 从锚点漂移到层内语义； 阶段三在状态范数超同类中位数 1.5 倍或增长过快时分裂出零状态空层 （绝不复制原层），给指数衰减 bonus 强制冷启动并在同类层间软均衡。 阈值默认取历史打分的滑动分位数（可切回固定值，历史不足时退回冷启动值）， 过载判定也用相对量而非硬编码绝对值。按阈值召回 Top-N 层加权注入 ΔH； fast weight 读出能量高时按 exp(−c·E_fw) 收缩注入，避免两次记忆读出同时拉高范数； 没有相关记忆时输出与标准模型逐值一致。池层共享同一份 KDA 权重、只各自持独立递推状态， 不新增任何参数——参数量预估与权重文件都不变，旧模型目录不受影响。 池快照落在 models/NAME/momw_state/（独立子目录，不进权重/配置契约）， 重启后按快照重建。推理界面可查看每层 γ/写入/‖S‖/Oja 步数/激活状态与当前阈值， 并可清空记忆池或切换静默激活（异步写模式下照常后台写入）。

优化器参杂方式
隐藏层 2D 权重矩阵 → Muon（Newton–Schulz 正交化 + RMS 对齐，lr 2e-2）；
embedding / lm_head / RMSNorm / 标量 / 卷积 → AdamW（lr 3e-4）。
两组各用各的学习率与动量，互不同步。
「全部 Muon」会把 embedding、lm_head 等 2D 矩阵也交给 Muon；1D 参数仍走 AdamW——矩阵正交化对向量没有意义。
目标模型
上下文窗口token 数，偶数
一次前向看多少个 token（偶数，user / model 各半）。窗口内每个位置在因果掩码下只预测下一个 token，整窗算一次平均 loss。越大越能学长依赖，但显存/内存按窗口平方涨；越小越快。保留它是因为它真实决定每步采样的窗口宽度，不是摆设。
steps / 文件固定采样次数
每个队列文件训练多少步：每步从该文件随机取一个窗口（block_size 个 token），窗口内逐 token 做 next-token 预测 → 整窗一次平均 loss → 一次梯度下降。步数与文件长度无关，是固定的采样次数；文件走完 steps 步即落盘归档。对比训练同样按这个步数跑。

GARGANTUA 是什么

            一个单机跑得动的通用 token 模型：默认配置约 10 亿参数
            （4+6 blocks、每 block 5 个 FFN；可用 d_model / block 数 / 共享权重调规模），权重按需加载，
            训练/推理/编解码全在本机完成，不依赖任何云服务。它不做「聊天框套壳」，
            而是把文本、音频、图像、视频、图元（矢量绘图）统一压进同一条
            token 流里，用同一个 Transformer 学。
          

            核心主张只有一句：一切模态最终都是 token + 时间步。
            时间步 { … } 是原子单位——压缩、丢弃、滑窗都不许把它切开。
          
1. 数据流：从任意模态到同一条 token 流
2. 一个 block 里到底有什么

            每个 block 的顺序是冻结的（2026-11-04 重排）：KDA → FFN → KDA → FFN →
            KDA → FFN → MLA-CSA → FFN → MLA-HCA → FFN → AttnRes。
            每个递推/注意力子层之后立刻接一个 FFN 做逐位置变换，5 个 FFN 是独立实例
            （GLU，d_ff=4096）；两个 MLA 视图分别是 CSA（4:1 可学习压缩 + 检索）与
            HCA（32:1 全局概括）。10 个计算子层各自先做一次 AttnRes 深度聚合与 RMSNorm，
            再累加进残差流；块末还有零初始化标量门把块输入混回输出。
          

            建模时可选权重模式：默认「分离权重」，encoder / decoder 各持一套
            block 参数（默认 4 / 6 层）；选「共享权重」则
            enc_blocks[i] 与 dec_blocks[i] 逐层共用同一批参数，因此两侧层数
            必须相等。共享只绑定参数、不合并实例——encoder 依旧双向，
            decoder 依旧按时间步因果；权重文件只落一份，参数量与磁盘占用约减半。
            模型宽度 d_model 建模时也可选（默认 1024，128 的倍数、无上限）：
            它只改语义向量宽度，注意力头数/头维、MLA 低秩秩与 FFN 隐藏宽度仍是冻结架构值。
          
第一个 Block 之后是记忆阀门：全局 fast weight（一个 KDA 层，状态跨调用持久，
            encoder 与 decoder 共享同一份）先用旧状态读出、再按门控 delta 规则写入。
            可选启用 MoMW（Mixture-of-Memory-Weights） 后，同址再并列一个无训练的三阶段记忆池：
            锚点播种（类别代表性 token Embedding 均值定初始路由）→
            状态特征漂移（SᵀS 增量幂迭代取主特征 E，γ 随写入次数增长，路由从外部锚点
            过渡到层内实际记住的语义）→ 空层分裂（‖S‖ 增长过快时新建零状态层、绝不 clone，
            配指数衰减 bonus 与同类软均衡）。按阈值召回 Top-N 层加权注入 ΔH；
            没有相关记忆就直接返回 H_1，退化为标准形态。
            池层共享同一份 KDA 权重、只各自持独立递推状态，不新增任何参数、不改检查点；
            未被召回的层完全不前向，状态也就不推进（未被召回则不遗忘）。
            锚点在首次前向惰性计算、不进检查点；状态按会话隔离，可在推理面板清空或静默激活。
          
3. 上下文：完整段 + 压缩段

            上下文 = 完整 1024 token + 压缩 3072 token。完整段不压缩，原样保留；
            压缩段是同一段内容的两份压法——CSA 检索视图（4:1）与 HCA 全局概括视图（32:1）。
            两个视图都读【压缩段 + 全部完整段】。压缩以时间步为原子，绝不跨步拆分。
          
4. 词表 base1.3.0：六段契约头 + config 决定的预留槽位

            词表不是「一个 txt」，而是一个文件夹（vocabs/<name>/{vocab.vfc, config.json}），
            基础词表带版本号 base1.3.0。ID 必须严格连续 0..N-1。
            契约头 = 六段：core 3（<caps>/<stop>/<draw:end>，
            最早就有的机制单标记，单开一类、<> 形态、无闭合、挂 TYPE_NONE）、
            boundary 6（[user] 等 [] 段边界）、
            system 3（{ } |）、slot N、
            typst 228（114 个 Typst 语法构造 × 显式开/闭对，
            <DOC>/</DOC> …
            <ATTR>/</ATTR>；
            <> tools，与 core 同类、不可显示、进 loss、挂 TYPE_NONE）、
            draw 9605。typst 插在 slot 之后、draw 之前
            （TYPST_BEGIN = 12+N、TYPST_END = 240+N）。
            N 不由 spec 钉死，而由每份词表 config 的 slot_count 决定：
            base 零预留（N=0 → HEAD_SIZE 9845、DRAW_BEGIN 240）；
            想要 N 个槽位就跑 gen_vocab.py --name NAME --slots N
            以 base 为模板生成新词表（HEAD_SIZE = 9845+N、DRAW_BEGIN = 240+N）。
            1.2.0 起不再预定义任何工具 / 排版 token：槽位按编号显示、语义
            由使用者在 spec.SLOT_DEFS 自己定义，执行先全部不接
            （工具台与测试台）；槽位整段挂 TYPE_SYS。
            可见区（数字 / 空白 / 符号 / emoji / 中日韩 / 英文 / 兜底字母 /
            1.1.0 追加的 474 个代码 token）长度由各词表自己决定；
            1.3.0 在末尾再追加 unicode_ext 区 3537 个字符（31 个 Unicode
            区块：拉丁扩展 / 西里尔 / 希腊 / 假名 / 数学符号等，category=regular），
            全表 vocab_size = 80262（76497 + 228 + 3537），MAX_VOCAB_SIZE 仍 100000。
            本轮 ID 整体位移（DRAW_BEGIN 64 → 12 → 240；1.3.0 中 draw 与
            全部可见区 +228），旧 .tokens / 权重 / 存档一律不可读。
            .tokens 用 token-6 编码（6 bit/字符，29 单字符 + 6 原子边界，终止码 63）。
          
5. 图元输出：先声明画布，再画

            一张图 = 1 段画布声明（<x> 数字… <x/> <y> 数字… <y/>，
            1..1920×1080 任意尺寸）+ N×9 个图元 token。
            每个图元 9 个字段，各自独立 bin 区间：x、y、w、h
            全部 1 token = 1 像素（上限即画布上限 1920×1080）、
            theta（3 bin/度，≥90° 交换宽高）、
            shape（背景/矩形/椭圆）、r/g/b（10 bit，1024 档）。
            专用的 <draw:end> token 表示绘画结束，之后的输出恢复为普通文本；
            Infer-Plug v1.0.0 检测到画布声明就实时渲染画布，时间轴可拖回任意一步。
          
6. 进程结构：常驻 server + 按需子进程
server/ 是一个常驻的轻量 HTTP 服务（纯标准库，不 import torch）；
            训练、推理、编解码这些重活全部交给 service/* 的子进程，
            用 JSON-lines over stdin/stdout 通信，空闲超时自动退出。
            好处是：换模型/崩一个服务不会带走整个应用，内存也能真正还回去。
